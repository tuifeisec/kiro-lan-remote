# kiro-lan-remote

## English

A standalone LAN gateway for viewing and interacting with local Kiro Agent sessions from a browser.

The project runs on a Windows host: the Node.js server connects to the local Kiro Agent Mux, while a phone or another browser on the LAN connects to the server over WebSocket. It provides session browsing, live conversations, history replay, task cancellation, permission approval, and reconnect recovery.

> **Security notice:** This project can drive the local Kiro Agent to read and write files and execute commands. It is intended for trusted LAN environments only. Use a random access key and stop the server when it is not needed.

### Features

- Access Kiro Agent sessions from a browser on the local network
- Session lists grouped by workspace
- Live streaming responses, reasoning progress, and tool calls
- Tool output, diffs, and terminal output
- Create sessions, send messages, and cancel the current task
- Forward permission requests for approval on a phone
- `session.load` history replay
- Incremental recovery after disconnects through `events.resume`
- Isolation between replay and live frames, preventing another connection's history load from polluting the current page
- Vue 3 + Pinia state projection architecture
- Single-file Vite build; runtime only requires one HTML artifact

### Requirements

- Windows 10 or later
- Node.js 20 or later
- Kiro installed and running on the host machine
- Permission for the current user to inspect the Kiro extension host process

### Installation

```powershell
npm install
```

### Build

The server serves the frontend from `public/index.html`. Rebuild after changing files under `src/`:

```powershell
npm run build
```

The build produces a single-file artifact:

```text
public/index.html
```

### Start

Start the server directly:

```powershell
npm start
```

The server automatically discovers the Kiro extension host and the local Agent Mux, then prints an access URL such as:

```text
http://192.168.x.x:8790/?key=<access-key>
```

#### Configuration

Override the default configuration with environment variables:

```powershell
$env:PORT = "8790"
$env:HOST = "0.0.0.0"
$env:ACCESS_KEY = "replace-with-a-random-secret"
npm start
```

Common environment variables:

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `8790` | HTTP/WebSocket server port |
| `HOST` | `0.0.0.0` | Listen address |
| `ACCESS_KEY` | Generated at startup | Browser WebSocket access key; an explicit random value is recommended |
| `PERMISSION_POLICY` | `ask` | Permission policy: `ask`, `allow-once`, `allow-always`, or `reject` |
| `AUTO_DISCOVER` | `true` | Whether to discover the Kiro Agent Mux automatically |
| `KIRO_MUX_PORT` | Empty | Manually specified Mux port |
| `KIRO_MUX_TOKEN` | Empty | Manually specified Mux token |
| `MODEL_ID` | Empty | Model ID used for new sessions |

To specify the Mux manually:

```powershell
$env:KIRO_MUX_PORT = "64155"
$env:KIRO_MUX_TOKEN = "your-mux-token"
npm start
```

### Protocol and permissions

The server connects to the local Kiro Agent Mux as an observer. Browser commands are forwarded through the server. Kiro `session/update` events are normalized by the server and then projected into Pinia state by the frontend event reducer.

History replay frames are delivered only to the browser connection that requested the corresponding `session.load`; they are not written to the reconnect buffer. Live events are still broadcast by session, with the frontend filtering them by `sessionId`. Permission requests are placed in a FIFO queue for the phone by default and forwarded to Kiro after the user makes a choice.

## 中文

一个用于通过局域网浏览器查看和操作本机 Kiro Agent 会话的独立网关。

项目运行在 Windows 本机上：Node.js 服务端连接本机 Kiro Agent Mux，手机或局域网内其他浏览器通过 WebSocket 连接服务端，完成会话列表、实时对话、历史回放、取消任务、权限确认和断线恢复。

> **安全提示：** 本项目可以驱动本机 Kiro Agent 读写文件和执行命令，仅适合在可信局域网中使用。请使用随机访问密钥，并在不使用时停止服务。

### 功能

- 通过局域网浏览器访问 Kiro Agent 会话
- 按工作区分组的多会话列表
- 实时流式回答、思考过程和工具调用展示
- 查看工具输出、diff 和终端输出
- 新建会话、发送消息和取消当前任务
- 将权限请求转交手机端确认
- `session.load` 历史回放
- 通过 `events.resume` 在断线后增量恢复
- 隔离回放帧与实时帧，避免其他连接的历史加载污染当前页面
- Vue 3 + Pinia 状态投影架构
- Vite 单文件构建，运行时只需要一个 HTML 产物

### 协议与权限说明

服务端以 observer 角色连接本机 Kiro Agent Mux。浏览器端命令通过服务端转发，Kiro 下发的 `session/update` 会先在服务端归一化，再由前端事件 reducer 投影到 Pinia 状态。

历史回放帧只投递给发起对应 `session.load` 的浏览器连接，不写入断线补发缓冲；实时事件仍按会话广播，由前端按 `sessionId` 过滤。权限请求默认进入手机端 FIFO 队列，由用户选择后转交 Kiro。
